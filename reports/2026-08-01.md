**差异点**：Flash 档一直是中庸档（Gemini Flash、Claude Haiku、GPT-4o mini）的定位——够便宜、够快、够用。DeepSeek 这次把"agentic capability"从 Pro 独占能力下放到 Flash 档，是这一代 open weights 阵营里第一次把 tool use / long-horizon 任务作为 Flash 档的一等公民卖点。对比 Kimi K2、Qwen3 系列，DeepSeek 是唯一从 v3.1 到 v4 一直在 API 层面直接对齐 Responses API 的开源方——这条工程路径决定了 Codex/Cursor/OpenCode 类工具接入零改造，护城河从"模型强"转向"生态钉子"。

**技术判断**：`0731` 说明是训练快照节点，节奏跟 Anthropic 的月度小改类似，不是从 v3 迭代出来。Responses API 原生支持意味着 tool 调用格式、multi-step reasoning trace、structured output 是 model-level 训练目标，不是 SDK 上贴的一层。开源标签在，但 "Flash" 档通常先 API 后放权重（V4-Pro 至今也只放了 base），实际能不能自部署要等几周。

**信号价值**：中端开源模型的竞争已经从 "GPQA/HumanEval 跑分" 走到 "能不能作为 agent backbone 直接替换 gpt-4.1-mini / haiku-4.5"。DeepSeek Flash + Codex CLI 组合如果真跑通，是自建 agent 栈的团队第一个真正意义上的"全套开源替代"选项。要关注的是它在长 horizon（>50 step）任务里的稳定性，以及 tool schema 严格遵守率——这两条是 Flash 档模型的历史软肋。

### 2. Port22 · ⭐⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/port22) | 250 votes · 32 comments (r=0.13)

**定位**：把 Mac 上跑的所有 coding agent（Claude Code / Codex / 其他 CLI agent）投到手机上——不是远程 shell，是每个 agent 的"待办列表 + 一按批准"。agent 卡在 permission prompt 时手机弹窗，你点一下实际选项（不是模拟键盘），agent 就继续跑。免费额度是 1 台 Mac + 2 个并发 session。

**差异点**：远程访问 dev 环境这条路上，Blink Shell / Termius / Warp Waves 都做过，但都是"把终端搬到手机上"——你还得手动看输出、手动敲键。Port22 的角度完全不同：agent 本来就在跑，你只是需要"被打断"和"批准/拒绝"这两个动作。这本质上是 agent 版的 GitHub push notification——把最痛的"20 分钟等一个 y/n"的 idle time 干掉了。跟 macOS 自带的 focus mode + 手动 SSH 相比，价值是"不用记得去看"。

**技术判断**：描述里 "attaches to what you already run, no wrapper, no config" 说明是靠拦截 macOS 端 agent 进程的 stdio 或 accessibility API 来识别 prompt 状态，然后走 push notification 服务转发到 iOS。真正的工程量在 prompt 状态机——不同 agent（Claude Code、Codex、opencode）的交互 UI 各不相同，"这是不是在等我"这个判断要么靠正则 + 心跳，要么靠模型分类，后者贵但通用。iOS 侧要把"具体选项"渲染成按钮，说明状态是结构化上传的，不是截屏 OCR。

**信号价值**：coding agent 正在变成一种"半异步"工作流——启动跑 30 分钟，中间只需要几个决策点。传统 dev 工具（IDE、终端）都是 sync-first 设计，跟这个新模式不匹配。Port22 是同一天出现的 5 个 "coding agent ergonomics" 类产品中最锋利的一个（其他有 AgentMicro、Tokimeter、Terminal Candy、TerminalWidget），说明这个方向已经形成明确的品类。做 agent infra 的团队应该开始把"push-style human-in-the-loop"作为标准接口设计，别再假设 UI 端是 always attached 的终端。

### 3. AgentMicro · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/agentmicro) | 169 votes · 7 comments

**定位**：本地优先的 macOS 菜单栏 companion，专门监督并行跑的 Codex Desktop / CLI 任务。看到状态、项目、耗时、结果一眼过，点一下跳到对应 Codex Desktop task。只读本地元数据，不上传 prompt / response / 源码 / 历史。

**差异点**：跟 Port22 是"同一个问题的两个答案"——AgentMicro 假设你人在电脑前但不想一直盯着 Codex 窗口，Port22 假设你不在电脑前。两者互补而非竞争。跟通用 menubar 工具（Bartender、iStat Menus）的区别在于 "task-aware"——它理解 Codex 的会话概念，不只是显示进程 CPU。跟 Warp Waves 的 "share your terminal session" 也不同，那是协作方向，AgentMicro 是个人观测方向。

**技术判断**：能显示 "task state / project / elapsed / results" 意味着它读 Codex 本地写的 task 元数据文件（Codex Desktop 在 `~/Library/Application Support` 下有结构化 log）。"never uploads" 明确的隐私承诺 + 开源标签，说明所有推断都在本地——没有云端聚合就意味着无法做跨机器 dashboard，这是主动放弃的功能面。菜单栏 app 的技术门槛低，护城河是"能否跟得上 Codex 版本更新的 log 格式变化"，这是耐力活。

**信号价值**：Codex 生态已经大到值得做第三方工具了——这是继 Cursor / Claude Code 之后第三个出现"周边工具品类"的 coding agent。做 agent 底层的团队应该学到的教训：把本地状态写成结构化文件（不只是 log 行），会自然长出周边生态。反之如果全部走 API，工具作者永远追不上你。

### 5. Kopai · ⭐⭐⭐
[PH](https://www.producthunt.com/products/kopai-the-marketplace-for-ai-agents) | 94 votes · 21 comments (r=0.22)

**定位**：让专家把自己的知识包装成 AI agent 出售的 marketplace，按 message 计价（不是按小时）。上传知识、无代码发布、买家付费即时问答。作者拿 70% 分成，平台负责发现、支付、信任层。带内置 eval 测试、加密知识库、multi-agent orchestration。

**差异点**：跟 GPTs / Poe / Character.AI 的 "custom bot" 不同——那些是订阅制或平台白嫖，Kopai 明确是 per-message 定价 + 70% 分成，直接类比 Substack / Cameo 的 creator economy 模式。跟 Fiverr / Upwork / Intercom's Fin 的 human expert 服务不同——Kopai 是"专家训练一个自己的替身，专家睡觉时替身赚钱"。跟 Consensus / Perplexity 的"AI 找答案"不同——这里的答案挂在具体专家名下，有 accountability。真正的竞品是尚未成熟的 "vertical GPT store"，比如 OpenAI 自家的 GPT Store 商业化路径至今没打通。

**技术判断**："multi-agent orchestration + built-in eval + encrypted knowledge base" 三样如果都真做出来，工程含量确实不轻。eval 是 marketplace 型产品的隐藏难点——买家没法自己评估答案质量，平台必须有客观分数体系。加密知识库大概率是"上传时加密 + 推理时选择性解密到 sandboxed context"，跟 Anthropic 的 Confidential Inference 是同一类方案的商业化。真实门槛在冷启动的 supply side——专家凭什么先把知识交出来。

**信号价值**：agent 经济的"付费模式"这条线终于开始有人认真做——过去两年绝大多数 agent 都在做能力，商业化默认 SaaS 订阅。per-message pricing 如果跑通，会引发一波"卖 agent 而不是卖时间"的知识工作者转型。做 AI agent 平台的团队应该关注它半年内的 supply-side 增长曲线：如果没法留住第一批高质量专家，marketplace 模式在 AI 时代会跟传统模式一样卡在冷启动。
