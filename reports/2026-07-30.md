### 1. SKI · ⭐⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/ski) | 580 votes · 311 comments (c/v 0.54)

**定位**：常驻桌面的语音层，专门包 Claude Code / Codex 这一类 CLI 编码 agent —— 按一个热键就说话，agent 也用语音答你，本地跑，Mac 与 Windows 都有。

**差异点**：市面上"给 AI 加语音"多半是 push-to-talk 的 dictation（Whisper 转文字后送进去），SKI 走的是双向语音对话 + 常驻 ambient 的路子，把编码 agent 当队友而不是命令行接受方。同类里 Cursor 的语音、Wispr Flow 都偏输入侧，没有 output 音频；Willow / Superwhisper 是通用听写。SKI 的赌注是"coding agent 值得有专属声道"。

**技术判断**：宣传"all on your machine, free" —— 大概率本地 STT（Whisper.cpp 或系统 speech API）+ 本地 TTS，Codex / Claude Code 走已有 CLI/SDK 接口。真正的工程量在 barge-in、meeting mode、"send it in your place" 这种 turn-taking 与打断逻辑上，不是套壳。

**信号价值**：一周内至少两款围绕 Claude Code / Codex 生态的新工具（另见 LangWatch tracker、tablo、agentOS）—— coding agent 已经足够普及到"agent 的 agent"这个二级市场值得独立创业。语音这条 modality 在开发者场景终于出了个像样解法，不再是"AI 编辑器加了个麦克风"。

### 2. Memmy Agent · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/memmy) | 527 votes · 206 comments (c/v 0.39)

**定位**：跨模型的用户记忆中枢 —— 一份 memory，Claude Code、Codex、OpenClaw、Hermes 共享，也可以自己接活干。Local-first，免费额度 200 万 ChatGPT token。

**差异点**：ChatGPT / Claude 各自都有 memory feature，但被锁在自家里。同类第三方尝试是 mem0（偏 SDK 定位，给 agent 开发者用）、Rewind（本地全记录但闭环）。Memmy 定位在"C 端用户 × 多 agent 客户端"，直接跟每个前端拼接，跟 mem0 是错开的市场。

**技术判断**：Local-first + "manage them anytime" 说明存在结构化 memory store + 前端注入（大概率 system prompt patch 或者 MCP server 形式）。真正的难点是"哪些 memory 对当前任务相关"—— 从描述看走的是分类召回而非纯向量检索。是否真正可控要看导出/删除粒度。

**信号价值**：agent 生态碎片化到"每个 agent 都要重复自我介绍"的痛点已经浮出水面。Memmy 是这周第二个明确赌"跨 agent 共享层"的项目（另一个是 agentOS 的 shared OS，Greplica 的 shared repo wiki）—— 中间件正在从"给一个 agent 加能力"转到"给一群 agent 加共享状态"。

### 3. agentOS · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/agentos-3) | 156 votes · 16 comments (c/v 0.10)

**定位**：给 agent 用的"Linux as a library"，基于 WebAssembly，号称比 sandbox VM 便宜 254 倍。当前接了 Claude Code、Codex、OpenCode、Pi、Eve、Flue。

**差异点**：agent sandbox 主流两派 —— E2B / Modal（云端 microVM，秒级冷启动）和 Docker/Firecracker 私有部署。agentOS 的 WASM 路线走的是 Cloudflare Workers 那套思路：不用 VM boot，用 WASI 提供 syscall 接口，冷启动几毫秒。代价是"Linux"其实是 WASI shim，能跑什么受 WASI 覆盖度限制（原生二进制、动态链接、fork 都是雷区）。

**技术判断**：254× 的成本对比通常是"无冷启动 + 无 idle 计费"下算的，对短请求确实可能，但只要跑一次 `pip install` 或调用只有 x86 二进制的库就崩。定位应该是"agent 的短命工具调用层"，不是"跑完整 dev container"。这个 trade-off 清晰的话，是有市场的。

**信号价值**：agent runtime 层的价格战开始了。E2B 一直没找到便宜的替代品，现在有人从 WASM 侧切入 —— 短期是补充而非替代，长期可能改变"给 agent 一个 shell"的成本模型。值得关注他们 WASI 兼容度到什么程度。

### 4. Yap · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/yap-5) | 150 votes · 24 comments (c/v 0.16)

**定位**：Mac 原生的语音听写，全本地，用 macOS 26 的系统 speech API。3000 行 Swift、4MB app、闲置 60MB 内存，MIT 开源，Frigade 团队做的。

**差异点**：本地听写这块已经有 Superwhisper（$70 买断、Whisper 本地）、Wispr Flow（云 + 本地混合、订阅制）。Yap 的杀器是"不需要下载模型"—— 因为 macOS 26 系统自带 SpeechAnalyzer，Apple 已经把模型内置到系统里了。这一点直接把 Whisper 派的 1-2GB 下载 + 首次启动等待打掉。

**技术判断**：4MB / 60MB 是 macOS 系统 API 的必然结果，不是自己压模型压出来的 —— 真正的工程决策是"敢不敢押 macOS 26 only"。押对了就是最轻的方案；押错了 macOS 25 及以下用户全没了。开源 MIT + 3000 行让替代者也很容易长出来。

**信号价值**：Apple 从 iOS 26 / macOS 26 开始把 speech + on-device intelligence 当基础设施推。Yap 是第一批只吃系统 API 的三方应用，验证了 Apple 的路径。做本地推理 / 隐私优先工具的方向上，"能用系统 API 就用"会是更多小工具的选择，不是自带模型。

### 5. Greplica · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/greplica) | 197 votes · 32 comments (c/v 0.16)

**定位**：给 coding agent 的自更新 wiki。持续从编码会话里提取决策、约束、gotcha、失败尝试、文件级上下文，按任务取回相关那部分。开源、本地跑，也有 managed 共享模式。

**差异点**：跟 Cursor Rules / .cursorrules / CLAUDE.md 相比，那些是人手维护的静态文档；Greplica 是从 session 里被动抽取。跟 Sourcegraph Cody 的 codebase context 相比，Cody 是纯代码索引，不记决策历史。真正对手是 mem0 for code / Continue.dev 的 agent memory，但 Greplica 把"跨开发者 + 跨 agent + 跨 fork"作为一等公民，视角是团队级而非单机。

**技术判断**：从 session 提取"decisions / constraints / gotchas"是 LLM 抽取任务，成败在两点 —— 抽取的信号噪声比（同一个 refactor 里的错误分支要不要留？），以及 retrieval 时"这次任务相关"的判断准确度。开源可以看代码验证，非套壳。

**信号价值**：coding agent 的记忆问题从"每个 session 都得重讲一遍"进入"跨 session 跨 agent 累积"阶段。这周同题有 Memmy Agent（用户级）、Greplica（代码库级）、Claude Code CLAUDE.md（人手写死），赛道明显在分化。团队协作维度的"code memory"目前还没有清晰赢家。
