### 1. Megaphone · ⭐⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/megaphone-3) | [官网](https://www.producthunt.com/r/NWV2HEY7XCIWPQ)

**定位**：Mac 上的开源本地语音输入 App。按住 Fn 键说话，直接把清理后的
文本贴进当前 App 的输入框；整条链路（识别 + 语言理解 + 命令解释）都跑
在设备上，没有账号、API key、订阅或服务器。MIT 协议，只支持 Apple
Silicon + macOS 26。

**差异点**：Wispro（今天 #8）、Superwhisper、Whispering 之类都是"云端
模型 + 本地包壳"，Megaphone 用的是 macOS 26 新暴露的 SpeechAnalyzer（
系统级 STT）与 Foundation Models（Apple 内置 LLM），把成本和延迟压到 0
的同时干掉了隐私顾虑。跟 Wispro 相比它没有多云端模型、能力上限更低，
但对 Apple 生态原生用户是完全不同的产品。

**技术判断**：真正的本地 pipeline，不是 wrapper。作者显然是等 macOS 26
的 Foundation Models API 落地之后才做的，用来做 filler 移除、自我更正
修复、按 App 上下文调整措辞、以及 inline 语音命令解释——这些以前必须
调云端 LLM。命令模式（Command Mode）是语音 macro 的雏形，跟 Raycast /
Alfred 的野心撞。

**信号价值**：Apple 的 on-device Foundation Models 落地后第一批利用它做
系统级功能的开源工具。语音输入这条赛道从"云端 STT + 云端 LLM 清洗"整体
被拉回到设备上，这对做 privacy-first 或 offline-first 产品是很强的
tailwind。值得 fork 一份读源码，看 Apple 提供的接口能到什么粒度。

### 2. AgentLoop · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/agentloop-2) | [官网](https://www.producthunt.com/r/56HF5BO4BC6T34)

**定位**：一个开源的 Codex 编排器，每个迭代周期都开一个全新的 worker +
critic 进程去执行任务：worker 按 GUIDELINES.md 里的 rubric 干活，critic
跑测试并把失败点写成"下轮修复笔记"，然后**丢掉整个上下文重开**。项目
文件本身承担长期记忆。零依赖 Node.js，本地 sandbox，可用 MCP 从 ChatGPT
控制。

**差异点**：主流方向（Cursor Agent、Claude Code 自己、Codex）都是"一个
长会话不断累积上下文"。AgentLoop 走的是反方向——把每次循环都当成一个
fresh call，把知识挤进 GUIDELINES.md 和 project 文件里，靠 critic 的
FIX_NOTES.md 传递单轮反馈。跟 aider 的 architect 模式和一些 self-critique
的研究工作思路一致，但把它做成了工程化 loop。

**技术判断**：真做过 agent 都知道长上下文会累积错误认知（"我上次已经
考虑过这个"其实没有）。fresh context + persistent artifacts 是一个被
学术界反复验证有效但产品化少的方向。零依赖意味着代码量应该很小、值得
读。critic 里的 PASS / SHIP 分级和 Polish 模式听起来像作者自己 dogfood
过的实用抽象。

**信号价值**：反长上下文的 agent 编排思路开始进入产品化视野。对做
"agents that build things"（不是聊天式 assistant）的方向有借鉴意义：
记忆放哪、循环边界怎么定、什么时候 hard-reset 上下文，都是可以复用的
patterns。

### 3. OpenCode Superapp · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/opencode-superapp) | [官网](https://www.producthunt.com/r/PWBY2H7UJXDKMZ)

**定位**：把 Codex 的 agentic 能力搬到本地/自托管模型上的原生 Mac
workspace：agent 能读项目、操作文件 / Git / 终端，还能语音对话，通过
"监督式 Computer Use" 操作其他 Mac 应用。走 skills + MCP 的扩展模型。

**差异点**：跟 ChatGPT Desktop / Claude Desktop 相比它把"模型选择权"
留给用户（cloud / local / self-hosted 都行），跟 Cursor / Zed 这些
编辑器相比它是"native workspace"而不是 IDE，操作面拓宽到系统级
（Computer Use + 语音）。跟 Anthropic Claude Code 相比它更侧重多模态
交互，且强调自托管。

**技术判断**：把三件事栈起来（agent runtime + 模型抽象 + Computer Use）
本身工程量就大，能声称"用 Codex + GPT-5.6 从 0 构建"暗示他们大量吃自
己的产品。真正的门槛在 Computer Use 的可靠性和权限沙箱——PH 上很难
判断，需要下载看。

**信号价值**：agent 产品这波开始分化：一边是 vendor-locked 但打磨精细
（ChatGPT / Claude Desktop），另一边是"自选模型 + 本地运行"的可组合
方向（这个 + Ollama 生态）。哪派赢跟"本地小模型能力何时够用"直接
挂钩。值得跟踪。

### 4. HOL Guard · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/hol-guard) | [官网](https://www.producthunt.com/r/7OII4S2Q6DHOCJ)

**定位**：一个坐在 agent 和系统之间的"防火墙"，拦截高风险操作——比如
删除生产数据库、泄露 secrets——在动作真正执行前做策略判断。开源、
免费，作者说下载量已过 400K。

**差异点**：这块生态目前主要是 vendor SDK 里塞的 guardrail（OpenAI /
Anthropic 都有内置），或者做 prompt injection 检测的独立库
（Lakera、Rebuff）。HOL Guard 定位在**运行时动作层**——不是"输入是
否可疑"，是"这个 tool call 该不该执行"。跟 permit.io、CedarPolicy
的 policy engine 思路一致，只是专门为 AI agent 场景切下来。

**技术判断**：核心难点是策略语言够不够表达能力，以及怎么在不了解具体
业务的情况下写出通用规则。400K 下载量如果是真的（PH tagline 常吹），
说明他们的规则库已经有一定成熟度。开源意味着可以直接看规则文件。

**信号价值**：agent 从"生成文本"走到"执行动作"以后，"策略层"是一个
必然出现的中间件。这类产品适合企业采购但小团队也会用。做 agent
产品的应该把这个加进 threat model 参考清单。跟 Ryan Peterman 那波
"agent runtime 安全"的思路对齐。

### 5. canitbebuilt · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/canitbebuilt) | [官网](https://www.producthunt.com/r/UVNVPKJ4HBVOEE)

**定位**：一句话描述一个硬件产品的想法，返回可行性判断（Buildable /
Buildable with changes / Heavy lift / Not viable）、100/1000/10000 台
量级下的 BOM 成本、子系统风险评级、目标市场的认证门槛、以及一个 3D
概念模型。两分钟出结果，不用注册。

**差异点**：LLM + 硬件跨界的样本很少，多数是"AI 帮你写 STL"或"AI 帮
你选组件"这种点工具。这个把 23 年硬件从业经验编码成 rubric，然后让
LLM 按 rubric 走全流程评估。类似"Cursor for hardware idea validation"，
把一个通常需要几周咨询的评估压到两分钟。

**技术判断**：核心不是 LLM 本身多强（他们用 GPT-5.6 Terra），而是
"评估维度定义 + 组件数据库 + 认证清单 + 3D 生成 pipeline"这些非模型
部分。BOM 报价能落到三个量级说明他们接了组件报价源；3D concept 大概
是文本 → CAD 生成模型。是"垂直 + 领域数据"的典型样本。

**信号价值**：一个信号——LLM 在 tacit domain expertise（老工程师
脑子里的东西）编码这条路上开始出实际能用的产品。可以类推到：给
律师用的合同风险快评、给运营用的选品可行性快评、给创业者用的商业
计划快评。判断力比生成力更值钱的场景才是这类产品的甜蜜点。
