### 1. AgentSky · ⭐⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/agentsky) | 455v / 55c · saas, developer-tools, artificial-intelligence

**定位**：把 Claude Code / Codex / Hermes / OpenClaw 这类 agent harness 做成
managed service——一键起一个"长跑"的云端 agent，跨 WhatsApp/iMessage/Slack/web/CLI
访问，带 session 恢复与完整历史。

**差异点**：现有对手大致两类——(a) IDE 里跑本地 agent（Cursor、Zed）；(b)
垂直 agent 平台（Devin、Factory）。AgentSky 走的是第三条路：**harness 无关的
agent-as-a-service**，你带 harness 与 LLM，它管进程生命周期、恢复、跨渠道
呈现。这条路目前只有零星尝试（sculptor.io、E2B 的方向），做成完整产品的
是第一个。

**技术判断**：核心工程量在 session 持久化（agent 内部 state + 文件系统快照 +
子进程树恢复）和跨渠道消息路由（WhatsApp/iMessage 网关都非 trivial）。不是
wrapper——tagline 里 "managed recovery" 和 "any harness" 就是在自证工程深度。

**信号价值**：**"agent 是新的进程，需要一层新的运行时"**——这个论点今年
Q2 开始被反复验证（Modal 的 sandbox 方向、Anthropic 的 Managed Agents、
Cloudflare Sandbox）。AgentSky 是把它做成消费级的第一批。对做 agent 平台
的方向意味着：**基础设施的抽象层正在从 "让 LLM 调用工具" 上移到 "让 agent
持续存在"**。

### 2. mpai · ⭐⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/mpai) | 119v / 13c · open-source, developer-tools, artificial-intelligence

**定位**：把 Codex/Claude Code 的本地终端 session 变成**多人共享**——队友
从另一台 Mac 加入你正在跑的原生 session，带自己名字发 prompt，host 保留
控制权，走 Tailscale 私网。

**差异点**：多人协作编辑 AI session 之前有两种做法——(a) 把 agent 搬到云
（前面 AgentSky、Murmell 就是这路）；(b) 屏幕共享 + Zoom。mpai 是**第三条**：
让 agent 留在原生 Mac 上，但把 session I/O 复用出去。这更接近 tmux 的哲学
（一个 session、多个 client），只不过 client 是异地的另一台机器 + 带身份标签。

**技术判断**：底层大概率是 PTY 复用 + Tailscale identity 注入到 prompt 头。
开源本身是加分——同类"agent 协作"产品几乎全闭源。

**信号价值**：AgentSky/Murmell/mpai 三个同日发布，从三个不同角度回答"多人
怎么用 agent"——**集中托管 vs. 共享画布 vs. 共享终端**。mpai 代表的
"轻量 P2P 派"是最容易被 Anthropic/OpenAI 官方在 CLI 里内建的一个（`codex share`
是可以想见的原生功能），值得关注它的成长速度和被吸收的时机。

### 3. Hand Wave · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/hand-wave) | 138v / 10c · ios, artificial-intelligence, lifestyle

**定位**：用 Meta 智能眼镜（也支持 iOS + web）把手语实时翻成文字与语音，
底层是训练在 Google FSBoard 上的轻量神经网络，本地推理。

**差异点**：手语识别产品长期是学术 demo，商用只有少数（如 SignAll）走
桌面摄像头 + 云端。Hand Wave 是**"眼镜 + 本地 NN + 开源模型"**的三件套，
这个组合此前没见过：戴眼镜的听障对话方的视角天然对准手语者，且本地推理
把延迟和隐私都拿下。

**技术判断**：模型走 open-source 路线（FSBoard 数据集训练），跑在设备上，
描述里明确说 wip 但方向清晰。这不是套 GPT——是 CV + 序列建模的真机器学习
工程。

**信号价值**：**smart glasses 从"信息叠加"迈向"能力叠加"的第一个消费级
样本**。Meta Ray-Ban 出货后一直缺"这个眼镜到底能替你做什么"的杀手用例，
translation / accessibility 是最有说服力的一类。同期看 Even Realities、
Brilliant Labs 也在往这个方向靠，Hand Wave 是把 accessibility use case
做实的先手。novel I/O + local-first + hardware 三命中。

### 4. yapyap · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/yapyap-3) | 153v / 11c · notes, meetings, audio

**定位**：本地优先的会议/语音录音——录音、转写、说话人识别、生成摘要/待办
都在本机完成，可选云端 LLM。核心机制是 "Lenses"：同一段录音可切换成
summary / todo / decision log 等不同视角，用户可装可写。

**差异点**：主流会议助手（Otter、Granola、Fireflies）都是"音频→云"，

了。yapyap 补齐了本地端 STT → speaker diarization → 摘要 这条完整链路，
且做了 Lens 这一层用户级扩展点——本质上是把 Notion AI 的"custom AI blocks"
搬到语音场景。

**技术判断**：Apple Silicon 上的 WhisperX/Distil-Whisper + 本地小 LLM
（大概率 Qwen/Llama 3B 量级）可完成大部分工作，硬活在 speaker diarization
的准确率与 Lens 的 sandbox 设计。tagline "Own your voice again" 明确
反对云 STT，产品定位一致。

**信号价值**：**"隐私 + 可插拔 pipeline" 正在成为本地 AI 应用的默认形态**
——不是简单的"离线版"，而是把用户可编程的中间层暴露出去。同期
yapyap / Snapdown（Mac 屏幕→Markdown 本地）/ Inventory（本地索引所有 agent
对话）三个同日项目共同印证：**Apple Silicon 上的本地 AI 已经过了 demo 期，
在打各自的产品化战役**。

### 5. Inventory · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/inventory-2) | 112v / 20c · productivity, artificial-intelligence, tech

**定位**：为 Cursor / Claude Code / Zed / Codex / Kiro 建的**本地私密索引**——
一次付费，无需注册和云端，跨所有 AI IDE 的历史对话全文搜索。

**差异点**：这类工具此前基本没有。IDE 各自的对话历史散落在本地 SQLite 或

承认了一个现实：**开发者的日常上下文正在从"代码 + browser"变成"代码 +
多个 agent 对话"**，需要一个新的搜索维度。

**技术判断**：本地嵌入 + SQLite/DuckDB 后端可以做出很好效果，工程重点在
每家 IDE 的历史文件位置和 schema 变更适配（Cursor 的对话格式几个月改一次）。

**信号价值**：**"AI 对话 = 新的一等公民数据"**——之前只有 chat 平台自己保存
（ChatGPT 记忆、Claude Projects），现在有独立第三方开始做跨平台搜索。这个
类目预计会快速拥挤（Raycast、Alfred、局部 IDE 插件都可能跟进），但先发者
有机会定义"conversation search" 的产品语言，值得跟踪。
