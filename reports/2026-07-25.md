### 1. Heard · ⭐⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/heard-2) | [Web](https://www.producthunt.com/r/HOUL4RGO5V5BZ2)

**定位**：给 Claude Code / Codex / Cursor 加一层"能听见"的旁白。macOS
本地服务把 agent 的输出实时总结成语音——想全程听就全程听，想安静就
只在报错或需要决策时开口。多个 agent 并行时，按 project 汇总"整体在
哪一步"，而不是五个终端同时说话。手机配对之后可以带出门。开源，个人
免费。

**差异点**：这不是又一个 TTS wrapper。核心是"parallel agent 场景下的
project-level 语音总结"这一步——同类里最像的是 Warp 的 agent
notifications 和 Vercel 的 background agent 提醒，但那都是 push 通知，
不是持续的语音伴随。加上手机配对（呼应上周 Pushary 的锁屏审批线）之后，
"眼睛不在电脑前"这段体验被又补齐了一块。开源 + macOS 原生，是硬门槛。

**技术判断**：真做起来的工程点：多 agent 输出流的拉齐与去噪、project
级 summarizer 的 prompt/model 选型（不能延迟太高，不能过度总结丢关键
错误）、macOS 本地 TTS 与后台音频路由、手机 pairing 走什么中继。
"summarize at the project level" 说明他们不是简单转发行日志，而是有一
层实时 aggregator——这块 latency vs fidelity 的 tradeoff 就是产品护城
河。开源意味着可以被验证不是壳。

**信号价值**：这一周开始能看到明显的模式：**agent-in-the-loop 的输入
输出正在按"人类感官通道"重新分层**。上周 Pushary 走的是触觉/推送
（锁屏审批），今天 Heard 走的是听觉（语音旁白），加上 Wisprkey /
Speechius / Speech To Markdown 都在把语音作为一等入口——2026 下半年
"agent 的 UI 层"会是围绕人类而不是围绕终端设计。做 agent 工具链的
团队要开始想：我的产品在哪个感官通道上？如果只在视觉+终端，会被这类
"绕开屏幕"的工具吃掉。

### 2. FluentDB · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/fluentdb-2) | [Web](https://www.producthunt.com/r/XDHRXK2IKT3XVD)

**定位**：macOS 原生的 AI 数据库客户端。PostgreSQL/MySQL/SQLite/SQL
Server 都支持，接 Anthropic/OpenAI 或直接复用你已有的 Claude Code /
Codex 订阅，也可以走 Ollama 跑本地模型。核心承诺：**只把 schema 给模型
看，不把数据给模型看**；AI 生成的每条 SQL 默认要人工点确认。

**差异点**：TablePlus + AI 的合体，但比 TablePlus AI 后加、比 DBeaver AI
更 Mac 原生。真正的差异在"schema-only + query-approval"这套安全默认，
以及"复用你已经在付的 Claude Code / Codex 订阅"这个渠道创新——绝大多
数 AI DB 客户端都在自己搭 metering，逼你再买一层 SaaS，FluentDB 直接接
你已有的账号，摩擦低了一个数量级。Ollama 支持让"完全离线跑"成立。
竞品：TablePlus AI（付费、闭源）、Chat2DB、Outerbase（云端）。

**技术判断**：Mac 原生 + 多 DB 驱动 + 三种 LLM 后端 + 本地审批 UI，这
不是套壳工程量。"schema not data" 说明他们做了一层 metadata-only
context builder，query approval 说明他们把 human-in-the-loop 做进了
primitive 而不是事后加。挑战在 schema 变复杂后（多 FK、view、CTE）
LLM 生成质量会不会掉——这类产品的护城河其实在于 schema 消化质量。

**信号价值**：**"复用已有 AI 订阅"作为渠道打法开始复制**——今天 FluentDB
和 Velane 都点名了 "works with your Claude Code / Codex subscription"。
Anthropic / OpenAI 的订阅正在事实上成为一层"AI 平台"，第三方产品把它当
credit provider 直接接入，绕开自己建 metering 的复杂度。这条通道会越来
越拥挤，对做 AI 工具的团队而言是必须要走的通道，对做 API 分发的团队而言
是要认真评估的威胁。

### 3. Second Brain for Mac and Windows · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/second-brain-cloudflare) | [Web](https://www.producthunt.com/r/6JNYYPRQZ2R2PT)

**定位**：跨 AI 工具的持久记忆层。装个桌面 app，5 分钟接上 Cloudflare
账号，从此所有 AI 工具共享一份自建的 knowledge graph。**关键点：数据存
在你自己的 Cloudflare account，不在他们的服务器上**。

**差异点**：memory / context 这条线上，Mem0、Zep、LangMem、OpenAI 的
Memories 都在卷，但主流都是"我托管你的数据"。Second Brain 走的是
**BYO storage**——你自己的 Cloudflare 账号里跑 D1 + R2 + Workers，
产品方只提供软件不碰数据。这是"用户自留数据面"这个近期热起来的模式
的另一个变种（Fluree AI 走 KG 数据平面、OpenWorker 走本地 desktop
agent、Second Brain 走用户自己的云）。桌面 app + 5 分钟接线也是关键
——之前需要 terminal / git 操作的门槛完全没了。

**技术判断**：走 Cloudflare 是聪明的选择——D1 存图/元数据、R2 存
blob、Workers 跑 embedding pipeline，成本几乎零、部署门槛低，还天然
拿到 CDN 全球分发。"自我构建的 knowledge graph"意味着他们在做实体
抽取 + 关系构建，而不是简单向量库堆。挑战是长期下这些 graph 会碎
化——recall 质量和 graph 演化机制会决定产品命运。

**信号价值**：**"用户自己的云是新一代 SaaS 数据面"** 这个叙事在成型。
比 fully local 门槛低（不用管硬件），比 SaaS 卖点强（数据主权），
Cloudflare / Supabase / Neon 的免费额度让这套模式经济上跑得通。
做 AI 应用的团队要认真考虑："我能不能让用户自带存储"这个选项是否
成立——如果成立，会是很强的差异化。

### 4. Velane · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/velane) | [Web](https://www.producthunt.com/r/7MNK32LQMZQ3P2)

**定位**：给 AI agent 用的"云"——code sandbox（0 冷启动） + 版本控制
+ 环境隔离（dev/staging/prod） + 800+ 第三方集成，整套平台由 agent
自己（Claude / Codex / Cursor）通过工具调用完全掌控。定位是
"agent 的 iPaaS + Vercel"。

**差异点**：这个位置上已经很挤：E2B（sandbox）、Modal（compute）、
Composio（工具集成）、n8n / Zapier MCP（iPaaS 面）、Daytona
（dev env）都是可比对象。Velane 的独特角度是"打包"——一站式给 agent
提供从 sandbox 到集成到环境的全套 primitive，且所有操作走 agent 而不
是人。"0 cold start" 是硬技术点（大多数 sandbox 服务冷启动 300ms+），
"800+ integrations" 是明显在对标 Zapier / Pipedream 的存量库。

**技术判断**：0 cold start 的 sandbox 通常靠预热池 + snapshot 恢复，
需要真金白银烧算力。800+ integrations 一般是靠爬 OpenAPI + 复用现成
connector 库（如 Nango、Cequence），不是从头写。版本控制 + 三环境
说明他们把 CI/CD 心智模型搬进了 agent 世界——这个类比合适度是产品成
败关键。挂 GitHub topic 说明他们打算走 developer 而非 no-code 路线。

**信号价值**：**"给 agent 用的 PaaS"这个位置正在被明确抢占**。过去
一周有 HarnessRouter（agent capability router）、Pushary（agent 审批
基础设施）、今天有 Velane（agent 云平台） + OpenComputer（agent 部署）
。这些产品都在赌同一个前提：agent 数量会指数增长，需要一层专门为
agent 而不是为人设计的 infra。窗口还开着但门在收窄——2026 Q4 之前
应该会有一两个赢家跑出来。

### 5. Capsomnia · ⭐⭐⭐⭐
[PH](https://www.producthunt.com/products/capsomnia) | [Web](https://www.producthunt.com/r/GHQA6Z5FHKWY5F)

**定位**：把 Caps Lock 键变成"合盖后 Mac 不休眠"的物理开关。开着
Caps Lock，合盖出门，Claude Code / Codex / 其他 agent、SSH、build、
下载全部继续跑。免费 + 开源 + 签名公证，无账号无遥测。

**差异点**：Amphetamine / Caffeinate / KeepingYouAwake 已经存在多年，
但都是软件里点一下或跑命令。Capsomnia 把它绑到物理按键上，并特别指
出"lid closed 也保持唤醒"——这个 lid-closed 保持算力的 case 官方
文档并不直接支持，需要绕 IOKit 的 assertions，说明他们做了真的
低层集成。"日本已有 6000+ 下载"是罕见的具体分发信号。

**技术判断**：签名 + 公证的开源 macOS 系统工具（不走 Mac App Store）
本身就是不小的工程门槛。lid-closed 唤醒常规做法是发 `PreventUserIdle
DisplaySleep` + `NoIdleSleep` assertion，但合盖后要保持 discrete GPU
和 CPU turbo 也醒着，需要更深的 IOKit 调用——从产品描述看是做到了。
Caps Lock 灯做状态指示是很好的物理反馈设计。

**信号价值**：这个产品本身不是 AI，但**它存在的原因100% 是 AI**。
"合盖之后让 agent 继续跑"是过去 12 个月才出现的 use case——之前没有
人会为 SSH 或 build 专门做这个物理开关的产品。这是**"agent 侧
生长出的次生工具生态"** 的一个具体样本：agent 不只是软件本身在变，
硬件/OS 层的日常操作也在被 agent 场景重新定义。做 agent 产品的团队
可以问自己：如果我的 agent 跑 30 分钟以上，用户会不会需要合盖走人？
如果会，这条使用路径完整吗？
